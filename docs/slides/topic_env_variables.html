Keep Your Secrets Out of Your Code

Environment variables in Python, Databricks, and R

J. Hathaway

The problem

Code gets shared. Secrets must not.


An API key typed into a script travels with that script — everywhere.

Where a hardcoded key ends up

API_KEY = "sk-abc123yourrealkeyhere"   # never

Git history

Deleting the line later doesn’t help. Old commits keep it.

Shared files

Notebooks, exports, screenshots, screen shares.

Everyone with access

Teammates, forks, and anyone who ever clones the repo.

What is an environment variable?

A named string the operating system hands to your program.

import os

os.getenv("API_KEY")                       # None if missing
os.environ["API_KEY"]                      # KeyError if missing
os.getenv("API_URL", "http://localhost")   # with a default

Always strings. Convert numbers and booleans yourself.

Python

.env files and python-dotenv

Three steps

2 Ignore it in Git

3 Load it in Python

First, install the package:

pip install python-dotenv

1 Write a .env file

One NAME=value per line, in your project folder.

.env
API_KEY=sk-abc123yourrealkeyhere
API_URL=https://api.example.com
DEBUG=true
  • No spaces around =
  • Quotes only needed if the value has spaces
  • # starts a comment

2 Keep it out of Git

.gitignore
.env

Then commit a template so teammates know what to set:

.env.example
API_KEY=your-key-here
API_URL=https://api.example.com

Add .env to .gitignore before your first commit.

3 Load it in Python

import os
from dotenv import load_dotenv

load_dotenv()                      # .env → os.environ

api_key = os.getenv("API_KEY")
api_url = os.getenv("API_URL")

Call load_dotenv() once, at the top of your entry script.

Use it, never print it

import requests

resp = requests.get(
    api_url,
    headers={"Authorization": f"Bearer {api_key}"},
)
print(resp.status_code)

200

Key is valid

401 / 403

Key is wrong or expired

Fail fast when a key is missing

def require(name):
    value = os.getenv(name)
    if not value:
        raise RuntimeError(f"Missing env var: {name}")
    return value

api_key = require("API_KEY")

A clear error at startup beats a confusing 401 ten minutes later.

Handy options

load_dotenv(find_dotenv())      # search parent folders
load_dotenv(".env.dev")         # a specific file
load_dotenv(override=True)      # .env wins over real env

config = dotenv_values(".env")  # a dict, os.environ untouched

By default load_dotenv() does not overwrite variables already set. Servers and CI can override your local file.

Databricks

Four options, safest to worst

Four ways to store a key

1 Databricks Secrets Encrypted. Output shows [REDACTED]. Best

2 %run config notebook Only safe if it reads a secret. OK

3 Cluster env variable Visible in cluster config. Not redacted. Weak

4 Hardcoded In the file and its history, forever. Never

Option 1 — Databricks Secrets

api_key = dbutils.secrets.get(
    catalog="workspace", schema="alice", key="my-api-key"
)
  • Value is never printed: output shows [REDACTED]
  • You choose who can read it
  • The notebook is safe to share or commit

On Free Edition, use Unity Catalog secrets. No CLI needed.

Set it up: three steps

0 Admin grants CREATE SCHEMA

once

→

1 You create a private schema

once

→

2 You add the secret

per key

Everything happens in notebooks or the Catalog UI.

0 Admin: allow schema creation

Run once, as a workspace admin:

GRANT CREATE SCHEMA ON CATALOG workspace TO `users`;

Or in the UI: Catalog → workspace → Permissions → Grant

1 Create your own schema

Use your own name in place of alice:

CREATE SCHEMA IF NOT EXISTS workspace.alice;

This schema holds your private secrets. No one else can read them.

2 Add the secret in the UI

  1. Catalog in the sidebar
  2. workspace → your schema
  3. Create → Secret
  4. Name: my-api-key · Value: paste your key
  5. Create

It is encrypted at rest and shows [REDACTED] from then on.

Read it at runtime

api_key = dbutils.secrets.get(
    catalog="workspace", schema="alice", key="my-api-key"
)

Use it. Don’t print it.

requests.get(url, headers={"Authorization": f"Bearer {api_key}"})

One key name, no collisions

workspace
├── alice    ← only Alice can read
│   └── my-api-key
├── bob      ← only Bob can read
│   └── my-api-key
└── charlie  ← only Charlie can read
    └── my-api-key

To share on purpose:

GRANT READ SECRET ON SCHEMA workspace.alice TO `bob@byui.edu`;

Rotate a key

In the UI

  1. Catalog → your schema → Secrets
  2. Open the secret
  3. Menu (three dots) → Edit → new value

In a notebook

from databricks.sdk import WorkspaceClient

w = WorkspaceClient()
w.secrets.update_secret(
    name="workspace.alice.my-api-key",
    value=new_key)

Needs WRITE SECRET. The new value works immediately.

Check it loaded, without leaking it

if not api_key:
    print("not set")
else:
    print(f"loaded, {len(api_key)} characters")

Databricks redacts secrets in output, but don’t rely on that alone. Confirm with a real API call and its HTTP status.

Option 2 — Share one config notebook

api_key_config notebook

api_key = "sk-abc123yourrealkeyhere"
api_url = "https://api.example.com"

Any other notebook

%run ./api_key_config

api_key is now defined.

  • One place to change or rotate
  • Holding the key in the config notebook is a poor version of a .env file

Option 3 — Cluster environment variable

import os
api_key = os.environ.get("OPENAI_API_KEY")
  • Anyone with Can manage on the cluster can see it
  • Not redacted: printing it leaks it
  • Not supported on serverless (job-level variables are Beta)

Option 4 — Hardcoded

API_KEY = "sk-abc123yourrealkeyhere"   # never

If a key was ever hardcoded, rotate it now. Assume it is compromised.

It lives in the notebook, its revision history, Git, and exports.

Local Python vs. Databricks

Takeaways

  1. Never hardcode a secret
  2. Locally: .env + python-dotenv + .gitignore
  3. On Databricks: Unity Catalog secrets
  4. Fail fast. Never print a value
  5. If it leaks: rotate first, clean up after

.Renviron

usethis::edit_r_environ(scope = "project")
.Renviron
API_KEY=sk-abc123yourrealkeyhere
API_URL=https://api.example.com

Restart R, then read it:

api_key <- Sys.getenv("API_KEY")

Add .Renviron to .gitignore.

.env files and safe use

dotenv::load_dot_env(".env")      # like python-dotenv
api_key <- Sys.getenv("API_KEY")
library(httr2)

request(Sys.getenv("API_URL")) |>
  req_auth_bearer_token(Sys.getenv("API_KEY")) |>
  req_perform()

Next: two ways to skip the file entirely.

askpass: type it when needed

# install.packages("askpass")
api_key <- askpass::askpass("Enter your API key")
  • Pops up a password prompt, typed characters hidden
  • Returns the value as a string
  • Nothing is written to disk

Good for quick interactive work. You retype the key each session.

keyring: store it once

# install.packages("keyring")
keyring::key_set("my-api")          # prompts once, then stores it
api_key <- keyring::key_get("my-api")
  • Saved in your OS credential store (Keychain, Credential Manager)
  • Read it back in any script, no file in your project
  • Closest R equivalent to Databricks secrets

Never put the key itself in your code. Only the name "my-api".
