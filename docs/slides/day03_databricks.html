Nested columns

Many patterns columns are lists of key/value pairs. Explode the list into rows, then unnest the pairs into columns:

devices = (patterns
    .select("placekey", "device_type")
    .explode("device_type")
    .unnest("device_type"))
placekey key value
222-223@8g7-2n2-td9 android 4
222-223@8g7-2n2-td9 ios 5

The same pattern works for related_same_day_brand, popularity_by_day, and the other key/value columns.

Databricks Free Edition

What it is

  • A free, serverless Databricks workspace
  • Spark notebooks with no clusters to manage
  • The same platform companies pay for
  • Sign up here

Limits to know

  • Notebooks time out after 2.5 hours
  • Go over quota and compute shuts off for the day
  • Python and SQL only (no R or Scala)
  • No commercial use

Three workspaces

1. Class

One workspace for all of us.

Open the class workspace

2. Team

Your whole team in one workspace, so you share notebooks and data.

One teammate creates it.

3. Personal

Your own space to experiment and practice.

You create it.

Set up your personal workspace

  1. Go to Databricks Free Edition and sign up.
  2. Use your university email. BYU-I emails can sign in with Google or Microsoft.
  3. Create a notebook to confirm it works.

Set up your team workspace

  1. One teammate creates a new Free Edition account for the team.
  2. That teammate invites everyone else:

User icon (top right) → Settings → Workspace admin → Identity and access → Users → Manage → Add user → Invite user by email

  1. Everyone accepts the invite and opens the same workspace.

Do this today, before you leave. You’ll need it for the proposal.

Load the semester data

One notebook loads everything

  1. Download load_semester_data.html from Slack.
  2. In Databricks, open Workspace → Import and choose the file.
  3. Attach the notebook to Serverless compute and click Run all.
  4. Wait 8 to 12 minutes. The last cell shows a summary. Every row should say ok.

Safe to re-run: anything already loaded is skipped. If a row says FAILED, run it once more, then post in Slack.

Finding it in the catalog

Click Catalog in the left sidebar. Data is organized in three levels:

workspace          ← catalog
├── cstore_snippet ← schema
│   ├── cstore_stores     ← table
│   └── cstore_payments
├── census
└── pattern_places
    └── pattern_places_data ← volume
  • A table has a schema you can query by name.
  • A volume holds files, like our Parquet files.
  • Click a table to see its columns, sample data, and details.
  • Names follow catalog.schema.table.

Reading it in a notebook

# A table, by its three-level name
stores = spark.table("workspace.cstore_snippet.cstore_stores")

# A file in a volume, by its path
places = spark.read.parquet(
    "/Volumes/workspace/pattern_places/pattern_places_data/places.parquet")

display(stores)

Use these exact names and paths. Don’t move or rename the data, so everyone’s code runs the same way.
